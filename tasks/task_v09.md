|                  |                                                        |
| ---------------- | ------------------------------------------------------ |
| **Слайс**        | E — Збереження та звіти                        |
| **Домен**        | пакетний імпорт довідника приладів                                          |
| **Складність**   | базова                                       |
| **Блоки курсу**  | ЛР3, ЛР5–ЛР6, ПР3–ПР5                                          |
| **Куди здавати** | `students/<прізвище>/variant-09/`             |

## 1. Кейс

Прилади зручно заносити не по одному, а списком із текстового файлу. Формат підтримує прості рядки, кратні прилади, змінні потужності та додаткові значення.

## 2. Дані варіанта

- звичайний рядок: `Fridge=150`
- кратний: `#MULTI Socket=100`
- змінна потужність: `VAR_Heater=2000`
- додаткові потужності: `POWERS_Drill=500`
- коментарі та порожні рядки ігноруються

## 3. Завдання

1. розібрати текстовий формат імпорту приладів;
2. створити прилади з коректною назвою та потужністю;
3. обробити позначки #MULTI, VAR_, POWERS_;
4. ігнорувати коментарі (#) і порожні рядки;
5. порахувати створені прилади та зібрати попередження про некоректні рядки;
6. експортувати створені прилади у JSON.

## 4. Що здати

- код у теці `students/<прізвище>/variant-09/`;
- `README.md` із коротким описом запуску та прийнятих рішень;
- тести на ключову логіку варіанта;
- приклад вхідних/вихідних даних.

## 5. Критерії

Оцінювання за загальною шкалою дисципліни («Критерії оцінювання СТП»).

| Результат | Бали |
|---|---|
| Завдання виконано повністю, код працює, рішення обґрунтоване | 90–100 % |
| Переважно правильно, незначні помилки/недоліки | 75–89 % |
| Основне виконано, але є суттєві недоліки | 60–74 % |
| Виконано окремі частини або код працює некоректно | 1–59 % |
| Не виконано / не відповідає завданню | 0 |

Додатково у цьому варіанті звертається увага на: парсинг тексту, обробка помилкових рядків, серіалізація у JSON.

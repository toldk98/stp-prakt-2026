## Мета

Відкрити свій варіант через **REST API** на FastAPI за схемою ПР7, додати
клієнт і тести; зібрати застосунок **end-to-end**. Зразок — еталонне ядро.

## Кроки

1. Реалізувати FastAPI-застосунок за схемою `pr7/api.md`: ендпоїнти варіанта.
2. Pydantic-схеми запиту/відповіді; некоректні дані → `422`.
3. Коректні статус-коди (`200`/`201`/`400`/`404`/`422`) та **узгоджений**
   JSON-формат помилок.
4. Підключити шар даних (`storage` із ЛР7) через ін'єкцію залежностей
   (`Depends`); логіка — у `analytics`, не в ендпоїнтах.
5. Клієнтський модуль на `requests`/`httpx`: викликає API, обробляє `400`/`404`,
   виводить результат і зрозумілу помилку.
6. Тести (`pytest` + `TestClient`): реалізувати план ПР8 — happy path,
   крайові, негативні; ізоляція через тимчасову БД.
7. **End-to-end демонстрація:** дані (CSV/БД) → сервер → клієнт → звіт.
8. `README.md`: запуск сервера й клієнта, приклади запитів, скріншот `/docs`.

## Артефакт

- FastAPI-застосунок варіанта, що запускається;
- клієнтський модуль із обробкою помилок;
- тести: unit + integration, зелені;
- end-to-end демонстрація;
- `README.md` із прикладами.

## Підсумок курсу

ЛР8 завершує наскрізний кейс: середовище → структури й функції → файли →
класи → модульний застосунок → git → база даних → REST API з тестами.
Студент має повний робочий застосунок свого варіанта.

## Типові помилки

- бізнес-логіка всередині ендпоїнтів;
- необроблені винятки → `500` замість `400`/`404`;
- тести ходять у робочу БД;
- клієнт падає на помилковій відповіді замість її обробки.

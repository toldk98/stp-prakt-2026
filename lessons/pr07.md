## Мета

Спроєктувати REST API для свого варіанта: ресурси, ендпоїнти, JSON-схеми,
обробка помилок і сценарій клієнта. Зразком слугує API еталонного ядра.

## Кроки

1. Відкрити `/docs` (OpenAPI) еталонного ядра `power_calc_edu`: виписати
   ресурси, методи, коди відповідей.
2. Для свого варіанта виділити **ресурси** (сутності → URL) за таблицею нижче.
3. Спроєктувати **ендпоїнти**: метод | шлях | призначення | параметри
   (path/query) | тіло запиту | коди (200/201/400/404/422).
4. Описати **JSON-схеми** запиту й відповіді (поля, типи, обов'язковість)
   та навести приклади.
5. Визначити **формат помилки**: узгоджене тіло; пояснити різницю
   400 / 404 / 422.
6. Описати **сценарій клієнта**: послідовність запитів (успішний і негативний).

## Орієнтовні ресурси за слайсами

| Слайс | Ресурси |
| ----- | ------- |
| A — прилади та профілі | `/api/appliances`, `/api/profiles`, `/api/profiles/{id}/items` |
| B — лічильники та показання | `/api/devices`, `/api/devices/{id}/readings`, `/api/pzem` |
| C — розрахунок та історія | `/api/calculator`, `/api/history` |
| D — об'єкти та доступ | `/api/locations`, `/api/locations/visible` |
| E — збереження та звіти | `/api/import/appliances`, `/api/export/report` |

## Артефакт

`students/<прізвище>/variant-NN/pr7/api.md`:

- таблиця ендпоїнтів;
- JSON-схеми запиту/відповіді + приклади;
- формат помилки та коди;
- сценарій клієнта (успішний і негативний).

## Критерії (2.5 бала)

| Складова | Бал |
| -------- | --- |
| Коректно виділені ресурси та ендпоїнти | 0.5 |
| Продумані JSON-схеми й приклади | 0.5 |
| Правильні статус-коди та формат помилок | 0.5 |
| Повний сценарій клієнта | 0.5 |
| Участь у розборі та захист рішень | 0.5 |

## Типові помилки

- дієслова в шляхах (`/api/getAppliances`) замість ресурсів;
- `200` там, де потрібен `201`/`404`;
- різні формати помилок на різних ендпоїнтах;
- схема без прикладів — незрозуміло, що надсилати.

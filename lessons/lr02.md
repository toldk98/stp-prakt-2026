# ЛР2. Структури даних, функції та модулі

|                  |                                                       |
| ---------------- | ----------------------------------------------------- |
| **Тривалість**   | 4 год                                                 |
| **Форма**        | індивідуально                                         |
| **Блок**         | 2 — ядро обробки в пам'яті                            |
| **Зв'язок**      | лекції 2–4; реалізує проєкт ПР1; готує ЛР3            |
| **Оцінювання**   | 5 балів                                               |

## Мета

Реалізувати ядро обробки даних свого варіанта **в пам'яті**: структури даних,
чисті функції, модулі. Покрити ключову логіку тестами.

## Кроки

1. Описати моделі даних варіанта (за рішенням ПР1): назви, поля, типи.
2. Додати демо-набір даних (як приклад — `seed.py` ядра): 5–10 записів.
3. Реалізувати **3–5 чистих функцій**, специфічних для варіанта: агрегація,
   класифікація стану, статистика, розрахунок. Кожна — один обов'язок.
4. У `docstring` кожної функції вказати складність `O(...)`.
5. Розбити код на модулі/пакет (`src/`), описати публічний інтерфейс.
6. Зробити CLI-демонстрацію: `python -m src.main` виводить зведення по варіанту.
7. Написати `pytest`-тести на кожну функцію + крайові випадки (порожній вхід,
   нульове значення, перевищення ліміту).
8. Швидкісна перевірка на великій кількості записів — підтвердити вибір структури.

## Що реалізувати у своєму слайсі

| Слайс | Орієнтовні функції/модулі |
| ----- | ------------------------- |
| A — прилади та профілі | CRUD-логіка в пам'яті, `total_power(profile)`, `classify(total, limit)`, `residual(profile)` |
| B — лічильники та показання | `mean/min/max_power(readings)`, `energy_delta(readings)`, сортування за часом |
| C — розрахунок та історія | `power_from_current(u, i, pf, phases)`, `classify(...)`, фільтрація історії |
| D — об'єкти та доступ | обхід дерева об'єктів, `subtree_load(node)`, `visible_locations(user)` |
| E — збереження та звіти | `parse_appliance_line(...)`, формування структури звіту, підсумки |

## Артефакт

- модулі в `students/<прізвище>/variant-NN/src/`;
- `tests/` із зеленими тестами;
- запуск `python -m src.main` із демонстраційним виводом;
- коміт у своїй теці.

## Критерії (5 балів)

| Складова | Бал |
| -------- | --- |
| Коректні структури даних і моделі | 1.0 |
| Чисті функції з одним обов'язком і docstring | 1.5 |
| Розбиття на модулі, зрозумілий інтерфейс | 0.5 |
| Працююча CLI-демонстрація | 0.5 |
| Тести, включно з крайовими випадками | 1.0 |
| Оцінка складності та швидкісна перевірка | 0.5 |

## Типові помилки

- функції з побічними ефектами (`print`/запис файлу всередині логіки);
- дублювання обчислень у кількох функціях;
- тести лише на «щасливий шлях»;
- змішування рівнів: дані, логіка й вивід в одному модулі.

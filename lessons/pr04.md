# ПР4. ООП: проєктування класів

|                  |                                                    |
| ---------------- | -------------------------------------------------- |
| **Тривалість**   | 2 год                                              |
| **Форма**        | індивідуально, розбір у групі                      |
| **Блок**         | 3 — структура коду                                 |
| **Зв'язок**      | лекції 5–6; продовжує ПР3; готує ЛР4               |
| **Оцінювання**   | 2.5 бала                                           |

## Мета

Спроєктувати **класи** варіанта: виділити сутності, розподілити
відповідальність, обрати композицію чи спадкування. Код не пишемо.

## Кроки

1. Виділити сутності варіанта (див. таблицю нижче).
2. Для кожного класу сформулювати **відповідальність одним реченням**.
3. Описати атрибути (з типами) та методи; для критичних атрибутів —
   `property`/`setter` із валідацією.
4. Визначити зв'язки: **композиція vs спадкування** за правилом
   «is-a» / «has-a»; обґрунтувати кожен вибір.
5. Побудувати діаграму класів (текстову/UML-подібну) зі зв'язками та кратністю.
6. Позначити, який клас — база/абстракція (якщо потрібно) і де достатньо
   `dataclass`.

## Сутності за слайсами

| Слайс | Класи |
| ----- | ----- |
| A — прилади та профілі | `Appliance`, `Profile`, `ProfileItem` |
| B — лічильники та показання | `Device`, `Reading` |
| C — розрахунок та історія | `Calculation`, `HistoryEntry`, `ProfileRef` |
| D — об'єкти та доступ | `Location` (дерево), `User` |
| E — збереження та звіти | `ImportResult`, `ReportRow` |

Підказка: «`Profile` **has** `ProfileItem`» — композиція;
«`TemperatureReading` **is a** `Reading`» — спадкування (застосовувати лише
за реальної потреби).

## Артефакт

`students/<прізвище>/variant-NN/pr4/classes.md`:

- таблиця класів: відповідальність | атрибути | методи;
- діаграма класів зі зв'язками та кратністю;
- обґрунтування композиції/спадкування й інкапсуляції.

## Критерії (2.5 бала)

| Складова | Бал |
| -------- | --- |
| Сутності виділені коректно, відповідальність чітка | 0.5 |
| Атрибути/методи з типами та валідацією | 0.5 |
| Обґрунтований вибір композиції/спадкування | 0.5 |
| Повна й коректна діаграма класів | 0.5 |
| Участь у розборі та захист рішень | 0.5 |

## Типові помилки

- спадкування заради повторного використання без «is-a»;
- «божественний клас» із десятком відповідальностей;
- публічні змінні без валідації;
- класи-сутності, що самі себе друкують або читають файли.

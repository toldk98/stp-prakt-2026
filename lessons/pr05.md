# ПР5. Аналіз архітектури ПЗ

|                  |                                                    |
| ---------------- | -------------------------------------------------- |
| **Тривалість**   | 2 год                                              |
| **Форма**        | індивідуально, розбір у групі                      |
| **Блок**         | 4 — архітектура                                    |
| **Зв'язок**      | лекції 7, 13–14; об'єкт аналізу — еталонне ядро; готує ЛР5 |
| **Оцінювання**   | 2.5 бала                                           |

## Мета

Проаналізувати архітектуру **еталонного ядра `power_calc_edu`** (шари, зв'язність,
патерни) і скласти **план рефакторингу** власного варіанта під цю архітектуру.
Об'єкт аналізу — реальний код, не власний.

## Кроки

1. Оглянути структуру ядра: `routes/`, `services/`, `storage/`, `models/`,
   схеми запитів/відповідей; визначити відповідальність кожного шару.
2. **Простежити запит end-to-end**, наприклад `GET /api/appliances`:
   route → service → storage → model → відповідь. Намалювати діаграму послідовності.
3. Знайти в ядрі приклади патернів і пояснити їх: ін'єкція залежностей
   (`Depends`), репозиторій, DTO/схеми, єдина точка входу.
4. Оцінити **coupling/cohesion** кількох модулів; знайти один реальний «запах»
   (довгий метод, дублювання, протікання абстракції) і обґрунтувати.
5. Порівняти еталон із власним варіантом: які шари вже є, яких немає, де
   змішано відповідальності.
6. Скласти **план рефакторингу** свого варіанта: що в який шар переносимо,
   які залежності прибираємо (основа ЛР5).

## Артефакт

`students/<прізвище>/variant-NN/pr5/architecture.md`:

- діаграма шарів ядра та їхніх відповідальностей;
- діаграма послідовності одного запиту;
- таблиця знайдених патернів (назва | де | навіщо);
- аналіз coupling/cohesion + знайдений «запах»;
- план рефакторингу власного варіанта.

## Типові помилки

- переказ коду замість аналізу (описано «що», а не «чому так»);
- діаграма послідовності без проміжних шарів;
- план рефакторингу без пріоритетів (усе одразу);
- «запах» без доведення, що це справді проблема.

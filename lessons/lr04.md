# ЛР4. Об'єктно-орієнтована програма

|                  |                                                       |
| ---------------- | ----------------------------------------------------- |
| **Тривалість**   | 4 год                                                 |
| **Форма**        | індивідуально                                         |
| **Блок**         | 3 — структура коду                                    |
| **Зв'язок**      | лекції 5–6; реалізує проєкт ПР4; інтегрує ЛР3         |
| **Оцінювання**   | 5 балів                                               |

## Мета

Реалізувати класи кейсу за проєктом ПР4: інкапсуляція з валідацією, сховище
в пам'яті, логування; перевести дані зі словників у об'єкти.

## Кроки

1. Реалізувати сутності з `pr4/classes.md` у модулі `domain`.
2. **Інкапсуляція:** приватні атрибути `_x` + `property`/`setter` з перевіркою;
   на некоректне значення кидати `PowerCalcDataError` (з ЛР3).
3. Якщо ПР4 передбачав базу/абстракцію — реалізувати обґрунтовано
   (наприклад, типізовані показники через базовий `Reading`); не вводити
   спадкування без потреби.
4. Замінити `print` на `logging`; при пропуску битих рядків — `warning`.
5. **Інтеграція з ЛР3:** CSV → об'єкти замість словників; той самий публічний
   інтерфейс модуля читання.
6. Реалізувати сховище в пам'яті (`Storage`/репозиторій) з методами
   `add`, `list`, `get`, `remove`.
7. Оновити CLI (виводить об'єкти) і тести: валідація, некоректні дані,
   робота `property`, крайові випадки сховища.

## Класи за слайсами

| Слайс | Класи |
| ----- | ----- |
| A — прилади та профілі | `Appliance`, `Profile`, `ProfileItem` |
| B — лічильники та показання | `Device`, `Reading` |
| C — розрахунок та історія | `Calculation`, `HistoryEntry` |
| D — об'єкти та доступ | `Location` (з дітьми), `User` |
| E — збереження та звіти | `ImportResult`, `ReportRow` |

## Артефакт

- модуль `domain/` із класами;
- `storage/` — сховище в пам'яті;
- CSV (ЛР3) → об'єкти;
- CLI, що працює з об'єктами;
- `tests/` — зелені (валідація, property, сховище).

## Критерії (5 балів)

| Складова | Бал |
| -------- | --- |
| Класи відповідають проєкту ПР4 | 1.0 |
| Інкапсуляція та валідація через property | 1.0 |
| Обґрунтоване використання спадкування/композиції | 0.5 |
| Логування замість `print` | 0.5 |
| Інтеграція CSV → об'єкти | 1.0 |
| Сховище та тести | 1.0 |

## Типові помилки

- `setter`, що нічого не перевіряє;
- валідація лише в конструкторі, а не при зміні;
- об'єкти-сутності, які самі пишуть у файл;
- `logging.basicConfig` у бібліотечному модулі (налаштування — у точці входу).

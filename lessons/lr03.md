# ЛР3. Файли, CSV, JSON. Обробка виняткових ситуацій

|                  |                                                       |
| ---------------- | ----------------------------------------------------- |
| **Тривалість**   | 4 год                                                 |
| **Форма**        | індивідуально                                         |
| **Блок**         | 2 — дані та алгоритми                                 |
| **Зв'язок**      | лекція 9; реалізує вибір ПР2; продовжує ЛР2           |
| **Оцінювання**   | 5 балів                                               |

## Мета

Замінити демо-дані у пам'яті реальними джерелами: читати дані з **CSV**,
записувати звіт у **JSON**, стійко обробляти помилки через винятки.

## Кроки

1. Підготувати `data/records.csv` для свого варіанта: 6–10 коректних записів
   і **навмисно битих** рядків (порожнє поле, текст замість числа, від'ємне
   значення, зайва колонка).
2. Модуль читання (`src/io/csv_reader.py`, назва довільна): розбір рядків і
   валідація кожного поля.
3. Власний виняток `PowerCalcDataError`; застосувати `try/except/else/finally`.
4. Биті рядки не валять програму: пропустити, зібрати в попередження й
   порахувати `skipped`; підсумок вивести в кінці.
5. Зберігати результат у `report/<domain>_<timestamp>.json` (час + дані звіту).
6. Обробити `FileNotFoundError` і випадок порожнього файлу — зрозуміле
   повідомлення, а не трасування.
7. CLI ЛР2 розширити джерелами: `--source mem|csv`.
8. `pytest`-тести: коректний файл, файл із битими рядками, відсутній файл,
   порожній файл.

## Формат CSV за слайсами

| Слайс | Колонки |
| ----- | ------- |
| A — прилади та профілі | `name,power,phase,qty` |
| B — лічильники та показання | `device,phase,timestamp,power,energy` |
| C — розрахунок та історія | `profile,limit,total,status,timestamp` |
| D — об'єкти та доступ | `location,parent,limit,load,path` |
| E — збереження та звіти | `name,power,phase,qty` + рядки `#MULTI`/`VAR_` |

## Артефакт

- `data/records.csv` (з битими рядками);
- модуль читання + запису звіту;
- `report/*.json`, згенерований програмою;
- CLI з `--source mem|csv`;
- `tests/` (4 сценарії) — зелені.

## Критерії (5 балів)

| Складова | Бал |
| -------- | --- |
| CSV читається коректно | 1.0 |
| Валідація та пропуск битих рядків із підсумком | 1.5 |
| Власний виняток і `try/except/else/finally` | 1.0 |
| JSON-звіт із позначкою часу | 0.5 |
| Обробка `FileNotFoundError` / порожнього файлу | 0.5 |
| Тести на 4 сценарії | 0.5 |

## Типові помилки

- «широкий» `except Exception` без розбору причини;
- падіння на першому битому рядку;
- `open()` без `encoding="utf-8"`;
- запис звіту з перезаписом попереднього (без timestamp);
- тести, що залежать від поточної дати.

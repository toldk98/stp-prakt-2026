# ПР2. Структури даних та алгоритми

|                  |                                                    |
| ---------------- | -------------------------------------------------- |
| **Тривалість**   | 2 год                                              |
| **Форма**        | індивідуально, розбір у групі                      |
| **Блок**         | 2 — дані та алгоритми                              |
| **Зв'язок**      | лекції 3–4; продовжує ПР1; готує ЛР2–ЛР3           |
| **Оцінювання**   | 2.5 бала                                           |

## Мета

Обрати структури даних і алгоритми для свого варіанта **на основі оцінки
складності**, а не інтуїції. Код не пишемо — це аналітичне заняття.

## Кроки

1. Виписати операції зі свого `pr1/design.md` (що робимо з даними найчастіше).
2. Для кожної операції визначити **структури-кандидати**: `list`, `dict`, `set`,
   стек, черга, дерево.
3. Оцінити складність базових дій для кожної структури: доступ, пошук за
   ключем, вставка, видалення, повний обхід.
4. Порівняти алгоритми ключової операції варіанта: наївний `O(n²)` проти
   оптимального `O(n)` / `O(n log n)`.
5. Обрати структуру й обґрунтувати: чому саме вона, що саме оптимізуємо.
6. **Трасування:** виконати свій алгоритм вручну на 5–10 записах варіанта,
   показати проміжні стани структури.

## Ключова операція за слайсами

| Слайс | Що аналізуємо |
| ----- | ------------- |
| A — прилади та профілі | агрегація потужності, пошук приладу за id, класифікація стану |
| B — лічильники та показання | статистика часового ряду, `energy_delta`, пошук максимуму |
| C — розрахунок та історія | фільтрація історії за профілем/датою, підсумки |
| D — об'єкти та доступ | обхід дерева (BFS/DFS), агрегація піддерева, видимі об'єкти |
| E — збереження та звіти | парсинг рядків у dict, групування записів для звіту |

## Артефакт

`students/<прізвище>/variant-NN/pr2/analysis.md`:

- таблиця «операція × структура × складність»;
- порівняння алгоритмів ключової операції;
- обґрунтований вибір структур даних;
- трасування на 5–10 записах.

## Критерії (2.5 бала)

| Складова | Бал |
| -------- | --- |
| Повний перелік операцій і структур-кандидатів | 0.5 |
| Коректна оцінка складності `O(...)` | 0.5 |
| Порівняння алгоритмів і обґрунтований вибір | 0.5 |
| Трасування без помилок | 0.5 |
| Участь у розборі та захист рішень | 0.5 |

## Типові помилки

- оцінка складності «на око», без підрахунку вкладених циклів;
- вибір `list` там, де потрібен пошук за ключем (`dict`/`set`);
- плутанина між складністю однієї операції та всього алгоритму;
- відсутнє трасування — вибір не перевірено на даних.

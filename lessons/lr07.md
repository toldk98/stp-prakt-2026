## Мета

Перенести зберігання даних варіанта в **SQLite** та виконувати аналітику через
**SQL-запити** замість ручних обчислень над списками.

## Кроки

1. Спроєктувати схему БД для сутностей варіанта (див. таблицю нижче):
   первинні/зовнішні ключі, індекс на колонку, за якою фільтруємо найчастіше.
2. Модуль `storage/db.py`: підключення до SQLite, створення схеми
   (`CREATE TABLE IF NOT EXISTS`), CRUD-операції.
3. **Завантажити дані з CSV** (ЛР3) у БД; повторний запуск не має дублювати рядки.
4. Реалізувати SQL-запити:
   - фільтр (`WHERE`), сортування (`ORDER BY`);
   - агрегати (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`);
   - `GROUP BY` для зведень;
   - `JOIN` двох таблиць.
5. Інтегрувати в точку входу: `--source db`.
6. Використовувати **параметризовані запити** (плейсхолдери `?`) і контекстний
   менеджер для з'єднання.
7. Формувати звіт із БД у CSV/JSON (модуль `reporting`).
8. `pytest`-тести на тимчасовій БД (`:memory:` або тимчасовий файл).

## Схема за слайсами

| Слайс | Таблиці | Індекс |
| ----- | ------- | ------ |
| A — прилади та профілі | `appliances`, `profiles`, `profile_items` | `profile_items(profile_id)` |
| B — лічильники та показання | `devices`, `readings` | `readings(device_id, recorded_at)` |
| C — розрахунок та історія | `profiles`, `calculations`, `history` | `history(created_at)` |
| D — об'єкти та доступ | `locations(parent_id)`, `users` | `locations(parent_id)` |
| E — збереження та звіти | `appliances`, `import_runs` | `appliances(name)` |

Приклад:

```sql
SELECT p.name, COUNT(*) AS items, SUM(a.power * i.qty) AS total
FROM profiles p
JOIN profile_items i ON i.profile_id = p.id
JOIN appliances a ON a.id = i.appliance_id
GROUP BY p.id
ORDER BY total DESC;
```

## Артефакт

- модуль `storage/db.py` зі схемою та запитами;
- завантаження CSV → БД (ідемпотентне);
- прапорець `--source db` і звіт із БД;
- `tests/` на тимчасовій БД — зелені.

## Типові помилки

- SQL, склеєний f-рядком (ризик ін'єкції);
- з'єднання без закриття (немає `with`);
- повторний імпорт CSV створює дублікати;
- забутий індекс — повільні фільтри на великих даних;
- тести, що пишуть у робочу БД проєкту.

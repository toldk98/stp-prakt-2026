# ПР6. Git та робота з конфліктами

|                  |                                                    |
| ---------------- | -------------------------------------------------- |
| **Тривалість**   | 2 год                                              |
| **Форма**        | пара (конфлікт розігрується на двох)                |
| **Блок**         | 5 — Git                                            |
| **Зв'язок**      | лекція 8; спільний репозиторій практик             |
| **Оцінювання**   | 2.5 бала                                           |

## Мета

Навчитися працювати з **гілками** та розв'язувати **конфлікти злиття**
у спільному репозиторії. Конфлікт розігрується штучно, у безпечному місці.

## Кроки

1. Повторити робочі команди: `status`, `log`, `diff`, `add`, `commit`,
   `branch`, `switch`, `merge`, `pull`, `push`.
2. Створити гілку під свою частину роботи й зробити зміни у своїй теці
   `students/<прізвище>/`.
3. У `playground/` є спільний файл `playground/shared.md` — викладач дає
   інструкцію, за якою ви та напарник редагуєте **той самий рядок**.
4. Отримати конфлікт: `git pull` (або `git merge`) зупиняється на конфлікті;
   знайти маркери `<<<<<<<`, `=======`, `>>>>>>>`.
5. **Розв'язати вручну:** зрозуміти обидві версії, обрати або об'єднати,
   прибрати маркери, `git add`, завершити merge.
6. Перевірити історію: `git log --graph --oneline --all`; пояснити, що сталося.
7. Продемонструвати безпечні операції: `git stash` (відкласти зміни) і
   `git revert` (відкат коміту).

## Артефакт

`students/<прізвище>/variant-NN/pr6/merge-report.md`:

- `git log --graph --oneline --all` до і після;
- пояснення причини конфлікту та способу розв'язання;
- власне правило, як уникнути такого конфлікту в майбутньому.

## Критерії (2.5 бала)

| Складова | Бал |
| -------- | --- |
| Гілка створена, зміни в ній (≥2 коміти) | 0.5 |
| Конфлікт отримано й коректно розв'язано | 1.0 |
| Історія чиста, пояснення зрозуміле | 0.5 |
| Продемонстровано `stash`/`revert` | 0.5 |

## Типові помилки

- видалення файлу замість розв'язання конфлікту;
- коміт із маркерами `<<<<<<<` усередині;
- втрата чужої зміни під час merge;
- робота в `main` замість гілки.

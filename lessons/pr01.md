# ПР1. Аналіз та декомпозиція задачі

|                  |                                                    |
| ---------------- | -------------------------------------------------- |
| **Тривалість**   | 2 год                                              |
| **Форма**        | індивідуально, розбір у групі                      |
| **Блок**         | вступний                                           |
| **Зв'язок**      | лекції 1–4; готує ЛР1–ЛР2                          |
| **Оцінювання**   | 2.5 бала                                           |

## Мета

Перетворити текст свого варіанта на технічний проєкт: постановку задачі,
декомпозицію, вибір структур даних і алгоритмічний план. **Код не пишемо** —
це заняття з проєктування.

## Кроки

1. Відкрити свій варіант у `tasks/task_vNN.md` і виписати доменні сутності
   (наприклад: *Прилад*, *Профіль*) та їхні поля.
2. **Постановка задачі:** вхідні дані, результат, обмеження, критерій готовності.
3. **Декомпозиція:** список функцій/модулів із сигнатурами
   (ім'я, аргументи, що повертає, які винятки).
4. **Вибір структур даних:** для кожної сутності — `list` / `dict` / `set` /
   `dataclass`; обґрунтувати вибір (доступ, порядок, пошук).
5. **Алгоритм:** псевдокод ключової операції варіанта (класифікація стану,
   агрегація, розрахунок потужності) + оцінка складності `O(...)`.
6. **Огляд еталона:** відкрити ядро `power_calc_edu`, знайти, як ці ж сутності
   та операції реалізовано в `models/` і `services/`; порівняти зі своїм планом.

## Артефакт

`students/<прізвище>/variant-NN/pr1/design.md`:

- постановка задачі;
- декомпозиція (таблиця функцій/модулів);
- обґрунтування структур даних;
- псевдокод ключового алгоритму + складність;
- порівняння з еталонним ядром (що збіглося, що зробили б інакше).

## Критерії (2.5 бала)

| Складова | Бал |
| -------- | --- |
| Коректна постановка задачі та визначені сутності | 0.5 |
| Повна й доречна декомпозиція | 0.5 |
| Обґрунтований вибір структур даних | 0.5 |
| Псевдокод і оцінка складності | 0.5 |
| Участь у розборі та захист рішень | 0.5 |

## Типові помилки

- декомпозиція «по файлах», а не по відповідальностях;
- структура обрана без обґрунтування («так зручніше»);
- складність вказана без аналізу циклів/пошуку;
- постановка без критерію готовності.
